# XP foundation

`awardXp` is an internal service. No route or learning action calls it yet.
The caller must authenticate the user, verify completion, enforce reward rules
and limits, and choose a stable award key. Never pass an HTTP request body through.

```js
const awardXp = require("./services/awardXp");
const result = await awardXp({
  userId,
  awardKey: "dialogue:course:dialogue:task-1",
  sourceType: "dialogue_task", // or vocabulary_review
  sourceId: "course/dialogue/task-1",
  amount: 10,
  ruleVersion: 1, // optional, defaults to 1
  // attemptId: optional ObjectId; no attempt model is introduced yet
});
// { awarded: 10, totalXp: 10, reason: "awarded", eventId }
// Duplicate: { awarded: 0, totalXp: currentTotal, reason: "already_awarded", eventId }
```

- An event and its lifetime total increment commit in one transaction.
- A unique `(user, awardKey)` index protects against concurrent duplicates.
- Reusing a key with a different amount, source, or rule version throws
  `XP_AWARD_CONFLICT`. A different attempt ID does not permit another award.
- Timestamps and Vietnam day keys are generated by the service, not the caller.
- `XPEvent` fields are immutable through normal Mongoose updates. Treat this
  collection as append-only in application code; raw database access can bypass
  Mongoose safeguards. Do not delete events when deleting learning content.
- Existing user documents need no backfill: the first `$inc` creates a missing
  `totalXp` field. Reading a legacy raw document may still require `totalXp ?? 0`.

## Database prerequisites

Use a MongoDB replica set or sharded cluster. Standalone MongoDB is unsupported;
there is no non-transactional fallback. The service owns its transaction and
must not be called inside a future learning transaction without refactoring it
to share that session.

Before connecting real learning actions, ensure the `xp_award_once` unique index
and query indexes exist. `XPEvent.init()` waits for normal Mongoose index setup;
if deployment disables `autoIndex`, explicitly run `XPEvent.createIndexes()` as
a deployment step. No deployment or database migration is performed here.

No daily totals, XP rules, ranking query, streak logic, attempt persistence,
or historical awards are implemented in this foundation.

## Tests

Run `npm test` from `server`. Tests start a disposable MongoDB 7.0.14 replica set,
exercise real unique indexes and transactions, and stop it afterwards. They do
not load `.env` or use the application database. The first run needs network
access to download the MongoDB test binary; later runs use the cached binary.
